# 完全 DSH 对齐方案（2026-09-08）

> 目标：把思考模型选择与思考强度**逐项对齐** DeepSeek Harness 官方语义（方案文档 §1.4 / §2 / §6 D2-D6 的"DSH 侧"），终止当前"语义对齐 + 网关运行兼容"的中间态。
> 范围边界：本方案只对齐 **BobWork 请求层语义与档位模型**（BobWork 是 harness 语义的"客户端/网关消费者"）；**不包含引入 DSH 运行时/换内核**（那是独立立项，见内核接口面盘点）。
> 依据事实：方案文档 §1.4（官方语义）、policy.ts / route.ts / presets.ts 现行实现（2026-09-08 核验）。

---

## 1. DSH 官方语义锚点（待对齐目标）

| 概念 | DSH harness 语义 |
|---|---|
| 档位 | `ReasoningEffortId = off \| low \| high \| max`（默认 high），适配器自持，core 只打 brand 不枚举 |
| 思考开关 | deployment 级 `thinking: enabled \| disabled`（模型能力声明，非请求内临时开关） |
| off 表达 | 不发送 `reasoning_effort`，改发 `thinking: { type: "disabled" }` |
| 思考模式参数 | 官方文档**未出现** `thinking_mode` 词汇；thinking 模式下 temperature 等无效 |
| 档位固定性 | 固定档位（epoch config），**无请求内动态降级** |

## 2. 现状差距（已核验代码）

| 项 | 现状 | 与 DSH 差距 |
|---|---|---|
| V4 档位 | UI 三档 low/medium/high → `thinking_mode: thinking/thinking_max/non-thinking` | 词表非官方；档位三值（max 藏在高档特判里）；无显式 off |
| 非 V4 档位 | `reasoning_effort` = level 同名（low/medium/high） | 无 off/max 值映射 |
| 动态降级 | 执行轮降一级 + C1 琐碎关思考（thinking.downgradeOnExecution/trivialPromptOff） | harness 固定档位无此语义（D6 待决） |
| 模型思考能力 | 请求级模型名正则推断（v4/reason/r1/z1/think/k2） | 应为模型/部署声明（thinking: enabled/disabled） |
| off 表达 | V4 发 `thinking_mode=non-thinking` | 应为 `thinking:{type:"disabled"}`（或网关扩展等价物，待探针） |

## 3. 分步

### S1 协议探针（前置，决定词表）
- 用已配置 deepseek-v4-* 网关发最小探针请求（max_tokens=1，temperature 等不动），对照三组字段：
  a) `reasoning_effort: high`（DSH 规范词）
  b) `thinking_mode: thinking`（现行）
  c) `thinking_mode: non-thinking` vs `thinking:{type:"disabled"}`
- 判定：网关接受哪些 → 词表去留与适配器映射据此定稿。
- 门槛：只发无害空转请求；结果记录在 §7。

### S2 档位模型贯通（D2 终态）
- 引入 `ReasoningEffort = 'off' | 'low' | 'high' | 'max'` 为**请求级统一档位**（接替 ThinkingLevel 三档的对外语义；UI 决策见 §5 拍板项）。
- `ThinkingLevel low/medium/high` → 映射：low→low、medium→high、high→max（见 §5 备选：保三档经适配器映射 / 直接改四档 UI）。
- policy 重写为纯适配器：`effortFor(level, config) → { apiField, value, thinkingDisabled }`，按 S1 探针结果决定 API 词（reasoning_effort 或 thinking_mode/thinking 对象）。
- V4 与非 V4 走同一条 effort 语义，仅"网关传输字段"由适配器分支。

### S3 模型思考能力声明化
- 模型配置 `thinking` 字段语义收紧为 deployment 声明（`enabled | disabled | 'off-capable'`? 以 S1 结果定），替代请求级正则推断；
- Auto 路由/模型选择不再"猜能力"，读声明排序（同 DSH deployment thinking 语义）。

### S4 插件化归属（D6 终态，见 §5 拍板）
- 执行轮降级 + C1 从"内核档位决策"迁移为**业务策略插件**（tool-pipeline 同款注册式或 policy 显式开关），内核只留固定档位；
- 开关位保留 thinking.downgradeOnExecution / trivialPromptOff / 新增 `thinking.harnessPure=false`（默认开插件=现网行为；true=纯 harness 固定档位）。

### S5 请求体与遥测对齐
- requestBody 按 effortFor 输出构造；去掉 V4 特判 `thinking_mode` 专用分支（收敛进适配器）；
- thinking 决策遥测沿用 done.thinking（字段含义随词表更新）；
- C7 上限、highDepth max_tokens 放大随 effort=max 对齐。

## 6. 风险与说明
- 词表若网关只认 thinking_mode：保持扩展词表 + 文档标注与 DSH 规范的等价映射（如 thinking→low、thinking_max→max），语义对齐而非字节对齐；
- 若 S2 把 low/medium 语义改映射（medium→high 等）会造成现网行为偏移 → 以 P-A/P-B 拍板为准控制回归面；
- max 档位若网关接受：high 不再必然 thinking_max（medium→high、high→max 两级化），与"high=thinking_max"现网习惯变化，需 UI 标签同步。

## 7. 探针结果（S1 已执行，2026-09-08 决定性）

**网关 = 官方 https://api.deepseek.com（deepseek-v4-flash，2026 现网）**。最小请求矩阵（max_tokens 64，观测 `reasoning_content` 长度）：

| 字段 | rcLen | 判定 |
|---|---|---|
| `reasoning_effort: none` | **0** | ✅ 关思考（官方枚举错误消息证实：`none/minimal/low/medium/high/xhigh/max`） |
| `reasoning_effort: max` | **124** | ✅ 思考最强 |
| `thinking_mode: thinking` | 93 | ✅ 生效（官方接受扩展词） |
| `thinking_mode: non-thinking` | **61** | ❌ **不关思考**（仍产出思考） |
| `thinking: { type: "disabled" }` | 0 | ✅ 关思考 |

### S1 结论（协议定稿）
1. **官方支持双词表**：`reasoning_effort`（规范，含 none…max）与 `thinking_mode`（扩展，thinking/thinking_max 生效）。
2. **现网 BUG（实测）**：C1 用 `thinking_mode: non-thinking` 关思考——**实际未关闭**（rcLen 61）！C1 省钱打折。真正关思考 = `reasoning_effort: none`。
3. **统一定稿**：V4 也走 `reasoning_effort` 词表（DSH 语义 off→`none`），删除 `thinking_mode` 专用分支；`off` 等价官方 `none`。
