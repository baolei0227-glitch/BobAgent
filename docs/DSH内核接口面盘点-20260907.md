### 1.2 每轮迭代子步骤（r0–r19 + r16 内部 a–s）

r0 needRebuildTools 消费 → r1 isFinalRound 快照 → r2 max_tokens 分级 → r3 requestBody 组装 → r4 恒带 tools（缓存承诺，lite 除外）→ r5 executionDowngrade + STEP_START → r6 thinking_mode/effort 落地 → r7 C7 1M 预检 → r8 completion 建立+退避重试（≤3）→ r9 流式收帧+usage → r10 C5 join → r11 scavenge 回收 → r12 无工具分支（退出判定）→ r13 forceFinalRound 解除 → r14 parsedToolCalls 排序/id 兜底 → r15 assistant 入账（C2 reasoning 原样）+ ASSISTANT_ATTEMPT → **r16 每 tool 子流程** → r17 停滞保护（STALL_LIMIT=3）→ r18 OCR 预算（≥4 停）→ r19 continue。

r16 每 tool：genSpanId → 参数 parse/repair（双失败 error）→ tool_repair → 重复调用检查（浏览器 pageUrl 豁免）→ `tool_call(pending)` → **咨询链**（顺序见下）→ `tool_call_update(running)` → coding_phase（coding 画像）→ args_transform → 20s keepalive → bobby/team_trigger → executeTool → grant(post) → login(post) → load_skill(post 联动) → tool_result 帧 + tool_span → read_attachment 引用 → lastPageUrl 刷新 → allToolCalls.push → result_compact(post) → 三连落账。

**咨询点顺序（硬性，跨 kind）**：`ask_user(pre) → search_capabilities(pre 全接管) → planner_confirm(pre) → tool_confirm(pre) → [running] → args_transform(pre) → [heartbeat/bobby/team] → executeTool → grant(post) → login(post) → load_skill(post) → tool_result → result_compact(post)`。planner 卡覆盖后跳过 tool_confirm。

### 1.3 退出条件与收尾

正常 break（toolCallBuf.size===0 分支内）：① forceFinalRound 且无工具 → break；② 正文非空 → break；③ 假完成双检（第一次 push"本轮你没有调用任何工具"+ completion_check + continue，第二次强制 break）；④ 纯问答（从未调工具）→ 身份防幻觉告警后 break。done 帧构造字段见 §2.2 SSE 表。收尾：TURN_END → persist（正常/异常双路径）→ close。无项目时跳过落盘（轨迹只留内存）。

**遗留死代码（盘点发现，2026-09-07 已清理）**：4017–4057 的 `hasFinishTaskCall/hasTodoWriteCall/isFirstRoundWithoutPlan` 位于 `toolCallBuf.size===0` 分支内恒 false——不可达，已删除（连同恒 false 的 `hasAnyToolCallsThisRound` 引用简化与从未读取的 `hasPlannedTask` 声明；`isContinuationFlow` 识别保留）。行为不变（tsc 0/lint 无新增/纯问答冒烟通过）。BASE prompt 仍要求模型主动调 finish_task，与实际"正文即交付 + 假完成双检"语义存在契约落差——模型仍可正常调 finish_task 结束（工具执行路径保留），此落差仅影响文案，暂不追改 prompt（记录待决）。

## 4. 替换切口建议

1. **route.ts 保留为适配器壳**：body schema、settings/profile 解析、ReadableStream+SSE 编码。
2. **runtime services 清单**：ToolRegistry/Executor、EventTrajectory、PendingHost、SkillService、MessageContextService（NodeBridge/VisionBridge/PDF/dynamicContext）、CompactionService、ApprovalService、ThinkingPolicyService、ModelResolver、UsageService、OutputFilesService。
3. **loop kernel 内 hook 与现注册表对齐**：九个咨询点固化 pre/post/scenario/args_transform/result_compact hook 接口，复用 tool-pipeline kind/phase。
4. **闭环调试资产做字节级对拍**：cacheguard.jsonl + `.trajectory/` + done.prefixSegments 四段 hash。

## 5. 风险与前置决策

风险：2000+ 行单闭包拆分回归面大；缓存前缀整段失效（~6 万 tokens 全价）不易测出；C2 字段在消息管线易丢（V4 400）；咨询点顺序隐性契约；轨迹双路径落盘漂移；遗留死代码若按注释重建会改变退出行为。

前置决策（替换前必须拍板）：① finish_task/todo_write 死代码删除或恢复（BASE prompt 契约落差）；② claimMismatchCorrections 计数器声明未自增（dead 或补全）；③ 会话态（chatStickyScenes、CacheGuard 状态）迁移归属；④ skills L1 目录注入位置（C8 约束下是否动）。
