# 项目经验记忆（Lessons Learned）方案

## 现状

BobWork 现有记忆机制分三层，但**缺少"项目级的可复用解题经验"**这一层：

| 机制 | 层级 | 存储 | 作用 |
|------|------|------|------|
| 节点压缩记忆 | 单节点 | 节点 `.md` 的 `## 压缩记忆` 分区 | 任务进行中的事实/状态 |
| preferences / work-reports / notebook | 全局 wanted | 全局 Markdown 三件套 | 用户偏好 / AI 反思 / 用户笔记 |
| **项目经验记忆（本方案）** | 项目 | **无（待新增）** | 项目完结后沉淀的**可复用解法库** |

关键现状结论：

- **无"解题经验"存储**。节点压缩记忆是"事实/状态"，`work-reports` 是"AI 自我反思"，都不是"这次项目里踩了哪个坑、怎么走通的"这种可直接复用的解题方法。
- **归档后端已就绪，前端未接线**。`archiveProject()` / `unarchiveProject()` 与 `archived`/`archived_at` 字段都在 [project-manager.ts](file:///Users/baolei/Desktop/BobAgent/projects/src/lib/project/project-manager.ts#L330-L369)，POST `/api/projects` 的 `archive`/`unarchive` action 也已实现（[route.ts L202-L218](file:///Users/baolei/Desktop/BobAgent/projects/src/app/api/projects/route.ts#L202-L218)），但 Sidebar 上**没有归档按钮**。
- 归档是**软标记**，不删除任何数据（节点 `.md`、`.project.db` 原样保留），作为"沉淀经验的触发点"是安全的。

---

## 目标

1. **归档即沉淀**：项目归档时，可选地把本次项目的解题方法存入项目级经验记忆。
2. **下次自动调取**：后续项目的对话中，AI 遇到相似问题能检索到相关经验并注入上下文。
3. **可追溯**：AI 引用经验时明确标注来源项目，用户可确认/纠正。

---

## 总体设计

核心思路：**归档 = 沉淀点**，把"解题经验"存为独立 Markdown，与"事实记忆"分离；检索时按相似度命中，注入到新项目的对话上下文。

```
归档动作 (POST /api/projects action=archive)
   │  前端弹确认框「是否保存本次项目的解决方法？」
   │  是 → 打开沉淀面板（AI 依据节点成果块生成候选经验清单）
   │       用户勾选/编辑 → 写入 <项目目录>/notes-memory/knowledge.md
   ▼
knowledge.md（项目级，人类可读/可编辑）
   │  写入时：同步更新全局检索索引（SQLite FTS5）
   ▼
下次任意项目对话 (/api/chat/route.ts)
   │  注入上下文处：按当前问题做相似度检索
   │  命中 → 把相关经验作为「相关历史解法」注入 prompt + 标注来源
```

## 一、存储设计：项目级 knowledge.md

每个项目目录下新增一个 Markdown 文件：

```
<项目目录>/notes-memory/
   ├── ...现有节点 .md
   └── knowledge.md          ← 新增，项目级经验记忆
```

**为什么用 Markdown 而非新 SQLite 表**：与现有 `preferences.md`/`work-reports.md` 同构，人类可直接阅读/编辑；不增改 DB schema；归档后随项目目录天然保留。

### 文件格式

每条经验 = 日期 + 标签 + 问题 + 方案 + 元数据，前两行可被检索：

```markdown
# Project Lessons

> 本项目的可复用解题经验（归档时沉淀）。AI 在相似问题时可参考。

## 2026-08-08 #markdown-image-import #node
问题：导入含图片的 Markdown 时图片外链失效
方案：下载图片到 materials/ 并改写为相对路径；用 ImageViewer 校验
  source_project: 上一个项目名
  source_node: n_xxx
  created_at: 2026-08-08 14:30
```

### 结构定义（TS）

新增 `src/lib/project/lessons.ts`：

```ts
export interface ProjectLesson {
  /** 序号（1-based，列表位置；删除时用） */
  index: number;
  /** 记录日期（YYYY-MM-DD） */
  date: string;
  /** #tag 标签（空格分隔，用于检索） */
  tags: string[];
  /** 问题描述（一句话，检索主键） */
  problem: string;
  /** 解决方案（写法，可被复用） */
  solution: string;
  /** 来源项目名（溯源） */
  sourceProject: string;
  /** 来源节点 id（溯源） */
  sourceNode?: string;
  /** 记录时间 */
  createdAt: string;
}
```

函数（对齐 `preferences.ts` 的既有模式）：

| 函数 | 说明 |
|------|------|
| `ensureLessonsFile(projectPath)` | 确保 `notes-memory/knowledge.md` 存在 |
| `listLessons(projectPath)` | 解析全部经验 |
| `appendLessons(projectPath, lessons[])` | 追加（按 problem 去重） |
| `removeLesson(projectPath, index)` | 按序号删除整块（含元数据） |

## 三、检索与自动调取

### 3.1 索引（写入时建，读取时查）

新增全局 SQLite 表 `knowledge_fts`（放 `.inbox.db` 同库，跨项目全局索引），复用现有 FTS5 trigram 中文分词经验（参照 `events_fts`）：

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS knowledge_fts USING fts5(
  lesson_id,
  project_id,       -- 来源项目
  problem,          -- 检索主字段
  solution,
  tags,
  created_at,
  tokenize = 'trigram'
);
```

- **写入时**：`save_lessons` 或 `appendLessons` 后，把该经验 `INSERT OR REPLACE` 进 `knowledge_fts`。
- **读取时**：用当前用户问题做 `MATCH` 检索，按 `bm25()` 排序取 top-N。

### 3.2 注入上下文（复用现有注入点）

在 [route.ts L764](file:///Users/baolei/Desktop/BobAgent/projects/src/app/api/chat/route.ts#L763-L766)（当前注入节点压缩记忆的位置）附近，加一步"相似经验检索注入"：

```ts
// 相似经验注入（项目级 Lessons Learned）
const lessons = await searchLessons(question, 3);   // 全局 FTS5 检索
if (lessons.length > 0) {
  parts.push(`## 相关历史解法（来源项目，仅供参考）\n\n${lessons.map(l => `- [${l.sourceProject}] ${l.problem}\n  → ${l.solution}`).join('\n')}`);
}
```

### 3.3 "AI 自动调取"的落地：被动注入 + 主动提示

分两层，避免过度自动化：

- **被动注入为主（默认）**：写入时做 FTS 索引，聊天时按问题相似度匹配，**命中才注入**（低侵入，不污染无关对话）。
- **主动提示为辅**：命中时在注入内容里带来源项目名，让 AI 在回复里说明"参考了之前 #xxx 项目的解法"，用户可追溯、可纠正。

### 3.4 可选：AI 显式读取工具

为避免"命中即注入"存在误判，可再提供一个工具 `read_lessons(projectPath?)`（对齐 `read_preferences`）：

- 无参：列出当前项目经验。
- 带关键词：检索全局相关经验。
- 让 AI 在系统提示条件式指示下调用（如"遇到疑似重复的任务时，先 read_lessons 查历史解法"），与被动注入互为补充。

## 四、与现有机制的分工（避免重复）

| 机制 | 保留 | 本次 |
|------|------|------|
| 节点压缩记忆 | ✅ 保留 | 不改 |
| 全局 preferences / work-reports / notebook | ✅ 保留 | 不改 |
| **项目经验记忆** | 新增 | 仅相似问题时调取，不全局每轮注入 |

分工原则：
- **节点压缩记忆** = 单个任务进行中的状态（保留现状）。
- **全局 preferences** = 用户长期偏好（保留现状）。
- **新经验记忆** = 项目完结后的可复用解法库（本次新增，只在相似问题命中时调取）。

## 八、风险与权衡

- **误注入**：相似度检索可能误命中无关经验 → 用"被动注入 + 来源标注"让 AI/用户可判断，检索阈值设保守。
- **记忆膨胀**：每个项目都沉淀会越来越多 → 按标签聚合并去重（problem 去重），检索只取 top-N。
- **隐私/范围**：经验是跨项目全局共享的，若用户希望某个项目经验私有，可后续加"仅本项目可见"标记（P4 可选）。
- **成本**：`suggest_lessons` 需调一次模型归纳 → 仅在用户主动选择"保存经验"时触发，不自动跑。
