# 笔记分类多标签化改造方案

> 目标：将笔记分类从「AI 自由层级 categoryPath」升级为「白名单标签 + AI 扩展自由标签 + 归一化」的多标签体系。
> 参考：datacore DIP-0014（命名空间双层结构）、brainkeeper（标签横向切割层级）。

---

## 一、背景与目标

### 现状问题

- 每条笔记只有单一 `categoryPath: string[]`（最多 3 级），本质是**单一路径归属**
- 分类名完全由 AI 每次自由生成，无白名单、无归一化 → 同类笔记分散（"工作" vs "工作事项"）
- 层级树依赖 AI 每次输出的一致性，模型不稳定时目录随之漂移

### 改造目标

1. **稳定轴**：`context`（场景）+ `type`（类型）白名单标签，AI 必选，保证顶层结构稳定可过滤
2. **灵活轴**：AI 可附加 0~3 个自由主题标签，覆盖个性化主题
3. **归一化**：标签统一格式 + 与既有标签相似合并，根治碎片化
4. **检索**：任意标签/组合标签过滤，不再依赖层级

---

## 二、方案总览

| 维度 | 现状 | 改造后 |
|---|---|---|
| 数据字段 | `categoryPath: string[]`（层级） | `tags: string[]`（白名单 + 自由，命名空间前缀） |
| AI 分类 | 自由输出层级 | 必选 `context:*` + `type:*`，可加自由标签 |
| 一致性 | 无保障 | 白名单约束 + 写入前归一化合并 |
| 检索 | 分类路径/关键词/日期 | 任意标签/组合标签/关键词/日期 |
| 展示 | 层级目录树 | 标签分组索引（白名单组 + 自由标签云） |

## 三、数据模型

### 新字段

```ts
interface NotebookEntry {
  id: string;
  title: string;
  content: string;
  tags: string[];            // 替换 categoryPath
  date: string | null;
  createdAt: string;
  updatedAt: string;
}
```

- `tags` 每条上限 **5 个**（2 个白名单 + 3 个自由标签）
- 白名单标签带命名空间前缀（`context:work`、`type:idea`），自由标签为纯主题词（`python`、`离婚诉讼`）
- 空 tags 兜底：`['context:other', 'type:note']`

### 存储格式（notebook.json）

```json
{
  "version": 2,
  "updatedAt": "<ISO>",
  "entries": [
    {
      "id": "nb-xxx",
      "title": "关于新证据链的想法",
      "content": "...",
      "tags": ["context:work", "type:idea", "证据链", "民事案件"],
      "date": "2026-08-20",
      "createdAt": "...",
      "updatedAt": "..."
    }
  ]
}
```

## 四、白名单设计

### 默认白名单（内置常量，可配置化）

| 命名空间 | 取值 | 说明 |
|---|---|---|
| `context` | `work` / `study` / `life` / `legal` / `other` | 场景（legal 面向法律用户主场景） |
| `type` | `idea` / `note` / `reference` / `todo` / `other` | 笔记类型 |

- 每笔记 **必选 1 个 context + 1 个 type**
- 无明确归属 → `context:other` / `type:note`

### 配置化（Phase 2）

`~/BobWork/wanted/notebook.config.json` 可选覆盖白名单，未配置时用内置默认。

## 五、AI 分类 Prompt 改造

### 新 SYSTEM_PROMPT（/api/notebook/route.ts callModelForNotebook）

```
你是一个个人想法整理助手。用户会输入零散的个人想法、灵感、随笔，请为每条想法：
1. 提炼一个简短标题（不超过 20 字）
2. 保留原文内容，可稍作润色使语句通顺，但不要改变原意、不要编造
3. 打标签（tags），规则：
   - 必须选 1 个 context 标签：context:work / context:study / context:life / context:legal / context:other
   - 必须选 1 个 type 标签：type:idea / type:note / type:reference / type:todo / type:other
   - 可附加 0~3 个自由主题标签（2~6 字，反映具体主题，如"证据链"、"Python"），不加命名空间
   - 总标签数不超过 5 个；不确定的归入 context:other

输出严格 JSON（不要 markdown 代码块，只返回纯 JSON）：
{
  "entries": [
    { "title": "...", "content": "...", "tags": ["context:work", "type:idea", "证据链"] }
  ]
}
```

### 解析兼容

- 优先读 `tags`；**兼容老输出** `category_path`（映射为自由标签，见迁移规则）
- 校验：tags 过滤出合法字符串，截断到 5 个；白名单标签校正（非法前缀剔除）

## 六、归一化算法（写入前执行）

### 6.1 格式归一化

```
输入标签 → trim → 去 emoji/控制符 → 英文转 kebab-case → 统一小写
```

- `"  Python "` → `python`
- `"离婚诉讼！"` → `离婚诉讼`（中文不动，去尾部标点）

### 6.2 白名单校正

- `context:*` / `type:*`：值不在白名单 → 归入 `other`（如 `context:unknown` → `context:other`）

### 6.3 与既有标签相似合并（防碎片化）

写入前读取 `notebook.json` 全部既有标签，对新自由标签按序匹配：

| 匹配规则 | 动作 |
|---|---|
| 精确相等 | 直接复用既有标签 |
| 包含关系（A ⊂ B 且差异仅修饰词） | 合并到更长标签 |
| 编辑距离 ≤ 1（中文按单字替换） | 合并到既有标签 |
| 均未命中 | 作为新标签保留 |

- 合并结果记日志（`[notebook] 标签合并: "工作事项" → "工作"`）
- 白名单标签不参与相似合并（只做精确校验）

### 6.4 上限控制

- 每条 tags ≤ 5：先保白名单 2 个，自由标签超出截断

## 七、存量数据迁移

### version 1 → 2

- `readNotebookStore()` 读到 `version !== 2` 且存在旧 `categoryPath` 时触发迁移：
  1. `categoryPath[0]` ∈ 白名单 context → `context:<它>`；否则 context 取 `context:other`
  2. `categoryPath` 其余层级拼为自由标签（最多 3 个）
  3. 补 `type:note` 兜底
- 迁移后 `version: 2` 原子写回（tmp + rename）
- 幂等：迁移完成即 version 2，不再触发

## 八、检索与展示

### 8.0 检索设计理念

- **标签是"精确寻址"，不是"范围限制"**：贴标签的目的不是缩小/排除检索范围，而是让目标内容被**精确命中**——`?tag=context:legal&tag=离婚诉讼` 直接定位到目标，而不是通过排除其他内容来逼近
- **标签是"反锁死"机制**：多标签让一条笔记**同时属于多个维度**（一条涉企合同纠纷笔记可同时挂 `context:legal` + `context:work` + `type:reference`），不被单一分类束缚；检索时从任一维度都能找到它
- 因此检索以**加性组合（AND）**为主：维度叠加收敛到精确目标，而非"选一个类排除其他"

### 8.1 过滤（filterEntries 扩展）

```ts
interface EntryFilter {
  query?: string;        // 关键词（标题+内容）
  tag?: string;          // 标签精确匹配（可多次 = AND）
  tagPrefix?: string;    // 命名空间前缀检索（列类目/计数用）
  from?: string;
  to?: string;
}
```

**匹配规则：**

| 表达式 | 语义 | 示例 |
|---|---|---|
| `tag=context:work` | 精确命中该标签 | 所有 work 场景笔记 |
| `tag=python` | 精确命中自由标签 | 所有 python 主题笔记 |
| `tag=context:legal&tag=离婚诉讼` | **跨轴组合（AND，加性收敛）** | legal 场景且涉离婚诉讼 |
| `tagPrefix=context:` | 前缀统计（faceted 导航） | 列出场景类目与计数 |
| `tag=context:*` | 通配前缀 | 全部场景笔记 |

要点：
- **精确匹配整串** → 白名单（`context:work`）与自由标签（`work`）互不污染
- **组合为 AND（加性收敛）** → 维度叠加精确定位，体现"寻址"而非"排除"
- **前缀检索**（`tagPrefix` / `context:*`）用于导航类目（列类目与计数），不用于内容过滤

### 8.2 索引展示（read_notebook index 模式）

新 `buildTagIndex()` 输出：

```
【场景】
  context:work（5 条）  context:legal（3 条）
【类型】
  type:idea（4 条）  type:note（3 条）
【主题标签】
  python（2 条）  证据链（2 条）  离婚诉讼（1 条）
```

- formatEntries 条目行显示：`[context:work · type:idea · 证据链] 标题（日期）`

## 十、分阶段实施计划

### Phase 1（最小可用版）

1. `tag-normalize.ts`：格式归一化 + 白名单校验 + 相似合并

5. 验证：存量迁移幂等、AI 输出 tags、标签合并日志、跨轴组合检索

### Phase 2（可选增强）

1. 白名单配置化（`notebook.config.json`）
2. 标签云 / 标签分组 UI（便签或 Wanted 面板）
3. 标签管理（合并/重命名/删除标签的批量操作）

## 十一、风险与兼容

| 风险 | 对策 |
|---|---|
| 存量数据迁移损坏 | 迁移先读后写，原子写（tmp+rename），失败回退旧库并记日志 |
| AI 输出老格式（category_path） | 解析层兼容映射 |
| 相似合并误合并 | 只做编辑距离 ≤1 / 严格包含，日志可追溯，不自动删除旧标签 |
| 便签快照（noteEntry）字段变化 | 快照透传 tags；旧快照（无 tags）按空处理 |

## 十二、验证用例

1. `/note 一个关于案件的灵感` → 返回 tags 含 `context:legal` + `type:idea` + 主题词
2. 连续写入 "工作事项""工作" → 第二次归一化为既有标签，不新增
3. 存量 notebook.json（version 1）→ 读取后自动迁为 version 2，幂等
4. `read_notebook` index → 输出场景/类型/主题三组标签索引
5. `?tag=context:legal&tag=python` 跨轴组合过滤正确（AND 收敛，非排除式）
6. `tagPrefix=context:` → 返回各场景类目与计数（faceted 导航）
7. 一条多标签笔记（`context:legal` + `context:work` + `type:reference`）从任一维度检索均可命中（反锁死验证）
