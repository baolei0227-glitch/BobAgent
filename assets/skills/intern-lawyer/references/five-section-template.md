# 五段式输出结构

法律分析、案件分析、责任评估、风险判断、胜诉可能性分析、如何处理、怎么办等场景，默认使用五段式结构。简单问题不得套用该结构。

## 触发关键词

分析、评估、判断、看法、意见、风险、胜诉、责任、如何处理、怎么办、法律分析意见。

注意："法律分析意见"属于纯分析，适用五段式结构；如用户要求的是"法律分析意见书"或"法律分析报告"（含文书性质），应转由 `legal-drafter` 承担。

## 五段式结构

必须按以下顺序输出，禁止跳过、合并、改变顺序或简化标题。

| 章节 | 标题 | 核心内容 |
| --- | --- | --- |
| 一 | 案件事实梳理 | 当事人信息、时间线、关键事实提取、信息缺口识别 |
| 二 | 案件要素分析 | 法律关系定性、主体资格分析、法律效力分析、程序要素审查 |
| 三 | 争议焦点梳理 | 焦点提取、分类（事实 / 法律 / 程序争议）、优先级排序、一览表 |
| 四 | 逐焦点深度分析 | 每个焦点含：法律依据 → 构成要件 → 举证策略 → 实务指引 |
| 五 | 结论与建议 | 案件总体评估、核心法律依据摘要、行动建议清单、风险提示 |

```markdown
## 一、案件事实梳理

[当事人信息、时间线、关键事实提取、信息缺口识别。]

## 二、案件要素分析

[法律关系定性、主体资格分析、法律效力分析、程序要素审查。]

## 三、争议焦点梳理

[提取争议焦点，按事实争议、法律争议、程序争议分类，进行优先级排序，并用 Markdown 表格呈现一览表。]

## 四、逐焦点深度分析

[逐一分析每个争议焦点。每个焦点均应包含：法律依据 → 构成要件 → 举证策略 → 实务指引。]

## 五、结论与建议

[案件总体评估、核心法律依据摘要、行动建议清单、风险提示。]
```

## 信息缺口交互

在"案件事实梳理"阶段，如果发现关键信息缺失，必须先展示"信息缺口提示"，让用户选择补充信息或基于现有信息继续分析。

优先使用可用的提问或选择交互能力；如果当前环境无法弹出交互框，则使用以下固定格式：

```markdown
## 信息缺口提示

目前缺少以下关键信息：

- [信息缺口 1]
- [信息缺口 2]
- [信息缺口 3]

请选择：
A. 我补充上述信息后再分析
B. 先基于现有信息继续进行初步分析
```

如用户选择继续分析，应在五段式中明确写明分析范围和不确定性。

## 结构自检清单

输出五段式分析前，必须自检以下项目全部通过才允许输出：

- 已判断不是简单问题。
- 已按"一、案件事实梳理""二、案件要素分析""三、争议焦点梳理""四、逐焦点深度分析""五、结论与建议"的顺序输出。
- 未跳过、合并、改名、调换顺序或简化五个章节标题。
- 第三部分包含争议焦点分类和 Markdown 表格。
- 第四部分对每个焦点均包含法律依据、构成要件、举证策略、实务指引。
- 第五部分包含总体评估、核心法律依据摘要、行动建议和风险提示。
- 如存在复杂关系，已使用 ASCII 图表辅助说明。
