# hand-drawn-map · 手绘地图风格示意图（L2 规则层 · 必读）

## 0. 定位（先读这条，决定本技能能不能用）

**真值 = 语义关系，不是地理坐标。**

本技能借用地图的**视觉隐喻**（路径、分区、地标、图例、指北针、藏宝图记号），
但**不承诺地理准确**：地标位置由叙事逻辑决定，不由经纬度决定。

- ✅ 适合：「我们的产品从 2024 走到 2026」「用户从认知到复购经历哪些触点」
- ❌ 不适合：真实地理地图（省界、城市相对位置、行政区划、导航距离）——**遇到时必须先向用户说明本技能不绘真实地理，并给出替代建议**（手绘示意 or 真实地图截图标注）

## 1. 何时用 / 何时不用

| 适用 | 转交其它技能 |
|---|---|
| 产品路线图、版本演进、里程碑地图 | 真实地理地图 / 需要比例尺 → 说明局限，不硬做 |
| 用户旅程图、体验触点地图 | 柱/折/饼等数据图 → `bob-ui` 的 `widget:antv` / `widget:chart` |
| 学习路径、成长地图、知识地图 | 标准流程 / 时序 / 状态图 → `bob-ui` 的 `widget:mermaid` |
| 藏宝图式叙事信息图（目标在终点） | 节点 > 20 的密集拓扑 → `bob-ui` 的 `widget:mermaid` |
| 业务流程 / 系统关系「地图化」 | 只在对话里看一眼、不要文件 → `bob-ui` 的 `widget:svg` |

> 本技能默认**落盘文件交付**（PNG + SVG）。用户明确说「只在对话里看看、不要文件」时，改走 `bob-ui` 的 `widget:svg`，不落盘。

## 2. 第一步：解析输入 → 归一成三要素

用户输入千变万化（一段话 / 一份大纲 / 一个表格），先归一化：

| 要素 | 含义 | 要求 |
|---|---|---|
| **地标 Landmark** | 地图上的兴趣点 | 名称（必）+ 一句话说明（选）+ 编号/图标（选） |
| **路径 Route** | 地标间的推进关系 | 默认单向线性；可分支、可合并 |
| **分区 Region** | 按阶段/主题把地标分组 | 淡色大区块 + 区名 + 可选区序 |

信息不全时：**先按已有内容画，缺失处用 ask_user_questions 一次问齐**（主题 / 地标清单 / 分区 / 起点终点），不要反复追问。

## 3. 第二步：构图模板路由

| 用户说的是 | 用模板 | 形态 |
|---|---|---|
| 路线图 / 旅程图 / 路径 / 阶段推进 | **T1 路径式** | 一条主干道路串联地标，左右摆动 |
| 里程碑 / 版本 / 时间线 / 演进 | **T2 时间线地图** | 路径 + 时间刻度 + 旗标 |
| 藏宝图 / 闯关 / 目标达成 | **T3 藏宝图式** | 起点船锚 → 虚线轨迹 → 终点 ✕ 标记 |
| 知识地图 / 概念全貌 / 主题分组 | **T4 群岛式** | 分区岛屿 + 桥/航线连接 |
| 城市地图 / 业务全景 / 系统关系 | **T5 城市地图式** | 网格街区 + 地标建筑 + 主干道 |

模板的完整参数与完整 SVG 示例见 L3 `02-composition-templates.md`。

## 4. 第三步：手绘质感四件套（本技能的灵魂 · 缺一不可）

**「手绘」≠「画得乱」**，而是四件套的**一致性的轻微不完美**。全部用纯 SVG 实现（技法见 L3 `01-style-library.md`）：

1. **纸底** —— 暖米白纸面 `#FAF7F2` + 极淡点阵/网格（禁纯白、禁渐变）
2. **抖动线条** —— 用二次贝塞尔弧代替直线、`stroke-linecap="round"`、统一笔宽档；禁止完美直线与硬直角
3. **手写感字体** —— 标题/地标名用手写体栈；**说明文字必须用系统栈**保证可读
4. **地标插画** —— 几何简化图标（山 / 树 / 房子 / 旗 / 星 / 船锚 / 圆点），线性 + 单色填充

> **一致性红线**：全图线条同一抖动幅度、同一圆头、同一笔宽档（3 档：细/中/粗）。混用 = 手绘感崩塌。

## 5. 第四步：视觉纪律（硬规则）

0. **主色 = 品牌 Purple `#4b3fe3`**（深色环境 `#6054f1`）；纸底 `#FAF7F2`；分区淡色 = 主色 6–10% 或中性米灰
1. **显式写色（必写）**：每个 `fill` / `stroke` 写 hex，不写 CSS 变量
2. **主色面积 ≤ 20%**：主色只落在路径主线、地标描边、标题、强调地标；大面积靠淡色块与纸底
3. **禁渐变、禁纯黑底、禁第三色相**（语义色——绿/红/橙——仅真实状态数据使用）
4. **留白**：四周留边 ≥ 48，地标之间 ≥ 40，元素不贴边、不重叠
5. **文字不自动换行**：长句用 `<tspan x="…" dy="1.5em">` 手动分行，或拆多行 `<text>`
6. **可读性优先**：手写体仅用于标题与地标名（≥18px）；说明/图例/注记用系统栈

## 6. 第五步：渲染落盘（5 步标准流程 · 照此执行，不要临时发明）

### 尺寸建议
| 场景 | 尺寸 |
|---|---|
| 横版叙事（路线图 / 旅程图 / 城市地图） | **1600 × 1000** |
| 竖版长图（手机转发 / 藏宝图） | **1200 × 2097** |
| 正方（知识地图 / 群岛式） | **1200 × 1200** |

`viewBox` 与最终尺寸一致；四周留边 ≥ 48。

### 步骤 1：写 SVG 源文件
用 `write_file` 写完整 SVG → `homework/<主题>-map.svg`。

### 步骤 2：包 HTML 渲染壳
用 `write_file` 写 `homework/.ai-workspace/map-render.html`，把 SVG 内联进固定壳：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<style>
  html, body { margin: 0; padding: 0; }
  body { width: 1600px; background: #FAF7F2; }
  svg { display: block; }
</style>
</head>
<body>
  <!-- 在此粘贴完整 SVG（与 .svg 源文件一致） -->
</body>
</html>
```

### 步骤 3：Chrome 无头渲染 PNG

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --window-size=1600,1000 --screenshot="<绝对路径>/homework/<主题>-map.png" "file://<绝对路径>/homework/.ai-workspace/map-render.html"
```

> `--window-size` 用实际宽高。Chrome 绝对路径不依赖 shell PATH。
> PNG 透明底 → 检查 HTML 壳 `body` 背景是否为 `#FAF7F2`；仍透明则补一层全幅 `<rect>` 后重渲。

### 步骤 4：视觉校验（必做）
用 `read_attachment` 读回 PNG，让视觉模型检查：文字溢出截断 / 元素重叠 / 出界 / 路径断开 / 配色对比。
发现问题 → 改 SVG 源文件 → 重走步骤 2–4 循环，直至通过。

### 步骤 5：清理并交付
`run_command` 删除中间壳文件，确认 `homework/` 只留 **PNG + SVG** 两份；正文汇报尺寸、构图模板、地标数量与文件路径。

## 7. 输出前自检（完整清单见 L3 `03-checklist.md`）

- [ ] 一图一句话能说清主题（地图标题 + 副标题）
- [ ] 有明确起点与终点，读者知道「往哪走」
- [ ] 地标 **5–9 个**（> 9 必须分区或拆图）
- [ ] 每个地标有名称，且编号或图标可辨
- [ ] **图例（Legend）齐全**：路径含义 / 分区含义 / 地标类型
- [ ] 手绘四件套齐全（纸底 + 抖动线 + 手写题 + 地标插画），抖动参数一致
- [ ] 主色 ≤ 20%，无渐变、无第三色相、无纯黑底
- [ ] 无重叠、无出界、留边 ≥ 48
- [ ] 产物 PNG + SVG 双格式落盘 `homework/`，中间文件已清理

## 9. 适用边界

- **必须说明局限**：真实地理地图诉求 → 明确告知本技能绘的是「地图风格示意图」，不保证地理准确
- **转交**：数据图表 → `bob-ui`；标准流程/时序 → `bob-ui` 的 mermaid；只在对话展示不落盘 → `bob-ui` 的 `widget:svg`
- **不做**：超过 20 个节点的密集拓扑（可读性崩塌，改 mermaid 或拆多图）
