# meeting-minutes — 会议纪要整理

## 适用

用户提供一段会议材料（可多源混合：文字消息、音频/语音转写、图片 OCR、文件提取文本），要求整理成结构化会议纪要。本技能同时服务于微信 `/meeting`（服务端自动整理）与 ChatNode 对话（用户上传材料后由 AI 整理）两条链路，输出结构完全一致。

## 输入处理（先分类再整理）

- **文字消息 / 文件提取文本**：直接作为会议内容使用。
- **音频 / 语音**：必须基于**真实转写文本**——优先使用系统已注入的转写（如音频附件自动转写结果），否则调用 `transcribe_audio` 工具真实转写。
  - ❌ 严禁凭文件名、大小、时长等元数据编造转写内容。
  - ❌ 若 STT 未配置或转写失败，必须明确告知用户"无法转写该音频"及原因，不得虚构。
  - ✅ 音频内容在要点中注明「语音转写」来源，确保可溯源。
- **图片**：基于 OCR 识别文本（系统标注 `[图片识别结果]`）；纯图表 / 无文字图片需请用户补充一句文字说明。
- 媒体转写/OCR 内容在整理时保留来源标注，不丢来源。

## 输出结构（严格按此，Markdown，不用代码块包裹）

```markdown
## 会议纪要：<标题>

**时间**：<会议时间段，从内容推断；推断不出写"待确认">
**参与人**：<从内容推断的与会者；推断不出写"待确认">

### 讨论要点
- 按话题归纳要点，逐条列出；语音/图片转写的内容注明来源（如「语音转写」「图片」）

### 决策 / 结论
- 明确写出的决定；无则写"无明确决策"

### 行动项
- [ ] 事项（负责人，时间）—— 负责人与时间从内容推断，推断不出写"待确认"

### 未解决项
- 悬而未决、需要跟进的问题；无则写"无"
```

标题优先使用用户提供的会议名；未提供时用「会议 MM-DD HH:mm」或从内容推断。

## 铁律

1. **只依据提供的内容整理**，严禁编造参与人、决策、负责人、时间。
2. 内容里没有的信息一律写"待确认"或"无"，不要脑补。
3. 保留关键数字、日期、地点、金额等事实信息。
4. 音频转写必须真实可溯源；转写失败时如实告知，禁止虚构会议内容。
5. 输出的是纪要本身，不添加与内容无关的寒暄或评论。

## 交付

- 对话场景：直接输出完整纪要 Markdown；用户可进一步要求保存为 .md 文件或发送 BobMail。
- 服务端场景（微信 `/meeting`）：由 executor 自动落 BobMail 收件箱（MEETINGS 分区），无需重复操作。
